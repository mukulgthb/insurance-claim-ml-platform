# Model artifact lifecycle

## Training versus inference

Training happens in training/train.py. It generates 2,000 synthetic
examples, splits them into 1,600 training rows and 400 test rows,
fits a preprocessing-and-classification Pipeline, evaluates it,
and writes a model artifact.

Inference happens through app/model.py. ModelService loads the saved
artifact during initialization. Its predict method applies the
already-fitted Pipeline to new feature values. It does not call fit
or execute the training script.

## Python source code versus serialized artifact

training/train.py contains the instructions for creating a model.

app/model.py contains the instructions for loading and using it.

artifacts/model.joblib contains a serialized dictionary with:

- pipeline: a fitted StandardScaler and LogisticRegression.
- metadata: model version, feature names, target definition,
  positive class, decision threshold, training timestamp,
  environment information, and evaluation metrics.

The artifact does not contain the full synthetic training dataset.
The training dataset can be regenerated by running the training code.

The artifact is not an HTTP server or a standalone application.
It requires compatible Python dependencies and serving code.

## Feature-order compatibility

The expected feature order is:

1. claim_amount
2. policy_tenure_days
3. previous_claims
4. incident_delay_days

ModelService verifies feature names at load time and constructs
the inference DataFrame in this order. Input dictionary key order
does not determine the model's feature order.

## Preprocessing compatibility

The fitted StandardScaler is saved inside the Pipeline.
Inference uses its learned training statistics rather than fitting
a new scaler on each request.

## Artifact trust and environment

Only the locally generated trusted artifact is loaded.
Joblib artifacts must not be loaded from untrusted sources.

requirements-lock.txt records the installed environment.
The same dependency versions should be used for training and serving.

## Phase 0 versioning limitation

The model version is synthetic-claims-v1.
Training currently overwrites the local artifact.
This is not an immutable model registry.

## Evaluation limitation

Evaluation uses held-out synthetic data.
The metrics do not establish suitability for real insurance decisions.
